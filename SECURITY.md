# Security

Use synthetic examples when reporting defects. Do not attach real environment files, private datasets,
credentials, access tokens, or logs containing personal data to public issues.

For a vulnerability that could expose data or enable code execution, use the repository's private
vulnerability reporting feature if available. If it is not available, open an issue requesting a
private reporting channel without publishing exploit details or sensitive data.

Only the latest published version is intended to receive fixes. See the README for the tool's scope
and input limitations; these utilities do not replace a complete security audit.
